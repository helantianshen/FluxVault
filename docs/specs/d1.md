# D1 持久化接入

本轮实现 Go REST API 与 Worker 原生绑定两套仓储，保留默认 mock。显式 `d1` 模式使用 D1 元数据和真实 Provider 适配器，不创建演示实例/文件，不用易失 mock 正文承载持久化记录。填写数据库配置本身不会切换模式。

持久化范围为文件、存储实例、API Key 和单管理员 bcrypt 摘要。管理员仅在空表中初始化，重启不覆盖已有密码。文件状态转换、实例能力复查与引用删除用条件 SQL 和数据库外键完成；不在网络请求间维持事务。写请求不自动重试，避免未知提交结果产生重复副作用。

API 保留原路径和业务响应结构；系统信息扩展 d1 模式、d1 数据库及不限总量（null），前端据此显示真实状态。D1 模式仍保留每文件 8 MiB 的代理上传限制。认证限流仍为进程/isolate 内存计数，不是分布式限流。

测试文件此前已按用户要求清理。本轮使用项目外临时验收工具进行隔离 SQLite、模拟 REST 和本地 workerd 检查；不恢复仓库内测试框架。远程 D1、真实 Provider、部署及推送不在本轮操作范围。

## 待填写的配置

本机已从示例生成以下私密副本，均被 Git 忽略；新检出需自行复制，禁止把凭据填入 example 文件。

| 后端 | 本地文件 | 必填项 |
| --- | --- | --- |
| Go | `apps/server-go/config.d1.local.yaml` | `d1.account_id`、`d1.database_id`、`d1.api_token`、`jwt_secret`；空管理员表还需 `admin_password` |
| Worker | `apps/worker-ts/wrangler.d1.local.jsonc` | `account_id`、`env.d1.d1_databases[0].database_name`、`database_id` |
| Worker 本地凭据 | `apps/worker-ts/.dev.vars.d1` | `JWT_SECRET`；空管理员表还需 `ADMIN_PASSWORD` |

Go 通过 D1 REST 访问，Token 需要目标账户的 D1 读写权限；Worker 运行时使用 `DB` 原生绑定，不把 Cloudflare API Token 放进 Worker vars。Wrangler 的账户认证与 Worker 应用凭据分开。管理员初始化密码要求 12–72 字节；JWT 签名密钥至少 32 字节，重启保持一致。初始化成功后可清空初始化密码；更改配置中的用户名/密码不会修改已有管理员，也不是密码重置机制。

默认配置仍是 mock。只有显式使用 D1 配置才启用持久化及真实 Provider。D1 仅保存元数据；实际上传还需创建存储实例，并按 `config/provider-secrets.example.json` 设置对应 Secret JSON。未配置 Provider 时上传会返回安全错误并保留 pending 记录，不会回退到 mock。

## 迁移与启动

新数据库按顺序应用 `database/migrations/0001_initial.sql` 和 `0002_file_name_search.sql`。应用启动不执行 DDL。下面命令从 `apps/worker-ts` 运行，必须先填写本地配置：

```bash
# 本机隔离 D1；不会操作远程数据库
npx wrangler d1 migrations apply DB --config wrangler.d1.local.jsonc --env d1 --local
npx wrangler dev --config wrangler.d1.local.jsonc --env d1 --local
```

本地 Worker 使用 `.dev.vars.d1`；前端以 `VITE_ADMIN_API_URL=http://127.0.0.1:8787` 启动。`--local` 数据与 Cloudflare 远程 D1 是不同数据库，不能用本地迁移结果代替远程迁移。Go 的 D1 模式始终访问远程 REST，不能连接 Wrangler 本地 D1。

远程迁移会修改实际数据库。确认目标并单独授权联调后，可将上述迁移命令的 `--local` 换成 `--remote`；本轮未执行。远程迁移完成后，从 `apps/server-go` 启动 Native：

```bash
go run ./cmd/server -config config.d1.local.yaml
```

Native 仍仅绑定回环地址，Public/Admin 分别为 18080/18081；前端管理 API 指向 18081。Worker 当前共用一个主机入口，生产域名隔离、路由及部署配置需另行完成；这里的配置不是生产发布配置。默认 `workers_dev: false`。

若数据库以前已应用 0001 且已有文件，0002 会为旧行留下空 `name_search`；启动会明确失败，避免搜索悄悄漏数据。需要先备份并用应用一致的 Unicode 小写规则逐行回填，不能用 SQLite 的 ASCII `lower()` 替代。空数据库无需回填。不要对已经手工执行过 0001 的数据库盲目再次执行建表迁移，应先核对 Wrangler 迁移记录。

## 接口与限制

`GET /admin/v1/system` 在 D1 模式报告 `mode: d1`、`database: d1`、`real_providers: true` 和 `max_total_bytes: null`；这表示启用了真实适配器，不表示 Provider 凭据已经验证成功。默认 mock 响应不变。`/healthz` 不执行实时数据库探测。

D1 写请求失败可能是提交结果未知；不得盲目重复上传或轮换，应先查询元数据。文件 pending/deleting 恢复规则不变。文件正文不进入数据库。跨两端使用同一数据库时需使用相同管理员签名密钥，并保持实例 Secret 引用配置一致。

参考：[D1 REST query](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/query/)、[Worker prepare / batch](https://developers.cloudflare.com/d1/worker-api/d1-database/)、[外键约束](https://developers.cloudflare.com/d1/sql-api/foreign-keys/)。
